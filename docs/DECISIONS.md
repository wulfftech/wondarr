### 2026-09-30 — Build session 4 (Phase 3)

| # | Topic | Decision | Why |
|---|---|---|---|
| 1 | A reference-only file is an owned song's file | An identified file in a `reference` library becomes the song's `song_file` (source `reference`) where it is; such a song is never searched, upgraded or replaced automatically, and a manual grab imports into the library and repoints the song without recycling the user's file | The app does not control that file; the user's folder stays exactly as it is |
| 2 | Confidence tiers (owner round 2 #7) | Auto-accept at ≥ `reference.auto_accept_threshold` (default 0.90), otherwise the Match queue. Tagged MBID within the length tolerance → 1.0; ISRC → 0.95; AcoustID → its score, capped at 0.89 unless the tags confirm the recording (or an untagged file's results all agree) **and** the length agrees; text search → 0.90 only when the resolver resolves it and both lengths are known and agree. An ISRC or text match whose length is unknown or disagrees is a candidate at 0.7 | A fingerprint of the start of a file cannot tell an extended mix or a live take from the album version (review of P3-02); a text match may come from a file name. Lowering the threshold below 0.90 lets capped results through — a deliberate user choice, left configurable |
| 3 | Covers are resized with ffmpeg | No imaging package | The image ships ffmpeg; ImageSharp's split licence is not OSI, SkiaSharp needs native assets |
| 4 | Deferred to later phases | The Opus → AAC/MP3 transcode setting moves to Phase 4 (with YouTube, the only Opus source); `artist.jpg` moves to the backlog | Keeps Phase 3 on the gate |
| 5 | Adoption copies, never moves | `adopt` mode copies the identified file into the target library through the import organizer and repoints the song (source `adopted`); the original stays, and later scans keep the row `Adopted`. A move mode is backlog | Reversible and safe on a first release; a move needs a recycle-bin story for the user's own folder |
| 6 | An AcoustID outage defers, it does not judge | A rate-limited or unavailable AcoustID leaves the file pending (and keeps any song it was linked to) and stops further lookups for that run; a lookup that throws defers only that file | "We could not ask" is not evidence; one bad file must not stop the files behind it |
| 7 | Worker commits carry no AI trailer | `scripts/worker.py` passes `--settings` turning off the CLI's co-author trailer | CLAUDE.md: no AI identifiers in commit messages (the history before 2026-09-30 has them; it is not rewritten) |
| 8 | Phase 3 branch | The session works in the worktree `.claude/worktrees/phase3-orch` (branch `worktree-phase3-orch`); workers branch from it (`WONDARR_WORKER_BASE`) and it is pushed to `main` | The orchestrator's own checkout stays usable while workers run |
| 9 | The Plex notice applies to every layout | Settings shows the "Prefer local metadata" notice for any library linked to a Plex section, not only flat/artist layouts; turning the setting on through the API (`PUT /library/sections/{key}/prefs?respectTags=1`, verified) is a later, explicit user action, never automatic | Live check 2026-09-30: with the setting off, Plex's online agent renamed a Plexamp-preset "Singles" pseudo-album to a real release; Wondarr must not change a user's Plex settings behind their back |
| 10 | A track-number title is not a title | Identification reads a title tag that is only a number as no title when it has a leading zero, equals the track number, or the artist tag carries "Artist - Title" (which is then split); "1999" or "22" by themselves stay titles | Live check 2026-09-30 on a real 96-file DJ set: every file was tagged title "001"…, artist "Artist - Title", so no fingerprint could be confirmed and every search asked for "001" — 0 of 96 identified automatically |
| 11 | An explicit album choice is pinned | `album_context.pinned` is set when the user chooses a song's album (`PUT` album context); the Compact task never re-plans a pinned song, and other songs may still join its album | Compaction re-plans everything else from scratch; without a pin it would undo a choice the user made on purpose |
| 12 | Compaction moves files through a hidden staging folder, one recorded step at a time | Move out to `<root>/.wondarr-compact/<move id>/` → Plex partial scan of the old folders, wait (start ≤ 30 s, finish ≤ 10 min) → `emptyTrash` → re-tag and place through the import's organizer (no new LRCLIB lookup; sidecars travel) → debounced scan of the new folders. Each step is saved on the file's `compact_move` row; a file found in staging is always finished before a new plan is made; a move that failed with its file still in place is dropped at the next plan; a Plex failure never stops the files going back | Plex never reconsiders album membership on rescan (LIBRARY_OUTPUT §7.2); verified live 2026-09-30 on Plex Media Server 1.43.4: the old album lost the tracks, the new one gained them, nothing left in the trash |
| 13 | Notifications never block, never leak | Event handlers only enqueue (bounded channel, drop when full); one 90 s budget per delivery (a `Retry-After` of at most 60 s is waited out once); secrets are masked as `********` and a mask sent back keeps the stored value; no URL, header or credential in a log line or an error; the Webhook payload keeps Lidarr's `eventType` values (`Grab`, `Download`, `DownloadFailure`, `Health`, `Test`) with a Wondarr `song` object; Discord embeds are cut to Discord's limits | *arr consumers of Lidarr's webhook keep working; Discord refuses a whole message when one part is too long |
| 14 | Merges are refused on any red step | `scripts/safe-merge.sh` returns from its check on the first failing step | Its check ran as an `if` condition, where bash ignores `set -e`: a red `dotnet test` was masked by a green frontend build and one merge landed with two failing tests |

| 4 | yt-dlp error taxonomy: retry-later vs blocklist | Bot check ("Sign in to confirm you're not a bot") and rate limit ("This content isn't available, try again later", HTTP 429/402) fail the item with the reason and let the song's backoff apply — never an immediate retry; geo, age-gated-without-cookies, private and unavailable videos are blocklisted for the song | A bot check is YouTube telling us to stop for now: looping is the failure mode the phase gate exists to prove absent; a video that can never be downloaded is dead weight in the candidate pool |
| 5 | A YouTube file's quality is `OPUS-160` whatever the container | The output policy (per library: AAC-256 `.m4a` default, MP3, or keep-Opus) changes the file, never the recorded quality id: a transcoded YouTube file keeps `OPUS-160` (id 28) | ADR-0008: a 320 cutoff must keep YouTube files upgradeable; recording the transcode's target bitrate would make them look met |
| 6 | YouTube is off by default with a one-time disclaimer | Enabling the source in Settings shows the ToS warning once; no cookies or accounts are bundled; the bgutil PO-token sidecar is the user's, pointed at through `youtube.po_token_base_url` | The research's legal section: YouTube's ToS prohibits automated access; the user decides, with their own credentials, on their own egress |
